🧠 WHAT YOU NEED TO KNOW BEFORE INTERVIEW (Basics Only)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

═══ DJANGO BASICS (know these) ═══

  □ What is Django ORM?
    » Write Python classes → auto-creates DB tables. No SQL needed.

  □ What is MVT (Model-View-Template)?
    » Model = DB table, View = request handler, Template = HTML.
    » But DRF replaces Template with JSON serializers.

  □ What is a serializer?
    » Converts Python objects ↔ JSON. Also validates input data.

  □ What is a migration?
    » When you change models.py, migrations update the DB automatically.
    » python manage.py makemigrations → python manage.py migrate

  □ What are decorators? (@api_view, @permission_classes)
    » Wraps a function to add behavior. @api_view makes a function an API endpoint.

═══ REACT BASICS (know these) ═══

  □ What is a component?
    » A reusable UI piece. Returns JSX (HTML-like syntax in JavaScript).

  □ What is useState?
    » Stores data that changes (form inputs, loading state).
    » When state updates, component re-renders.

  □ What is useEffect?
    » Runs code after render. Used for API calls.
    » Empty [] = run once on page load.

  □ What is Context API?
    » Shares data across components without passing props manually.
    » AuthContext stores login state — any component can use it.

  □ What is React Router?
    » Client-side navigation. Changes URL without page refresh.
    » BrowserRouter → Routes → Route path="/products" → ProductsPage

  □ What is an Axios interceptor?
    » Runs before every API call. Attaches auth token automatically.

═══ GENERAL BACKEND CONCEPTS (know these) ═══

  □ REST API
    » URLs represent resources: /api/products/, /api/orders/123/
    » HTTP methods: GET (read), POST (create), PATCH (update), DELETE

  □ Authentication vs Authorization
    » AuthN = "Who are you?" (login + token)
    » AuthZ = "What can you do?" (admin vs customer permissions)

  □ CORS
    » Browser security — blocks frontend (localhost:3000) calling backend (localhost:8000)
    » django-cors-headers fixes this

═══ YOUR PROJECT-SPECIFIC (definitely ask) ═══

  □ Why two auth systems? (admin token vs customer token)
    » Admin uses DRF's built-in Token model. Customer uses custom token field on Customer model.
    » I created LenientTokenAuthentication so customer tokens don't crash admin auth.

  □ How does bill splitting work?
    » API calculates total → divides equally or custom → creates PaymentStatus per member.
    » Each member can only mark their own payment as paid.

  □ Why pickup mode instead of delivery?
    » Target audience = small kirana stores. No delivery fleet needed.
    » Proven model — Walmart, Target, Amazon all use "Buy Online, Pick Up In Store."

  □ What was the hardest bug?
    » DRF's TokenAuthentication was returning 401 for customer tokens before the view could check them.
    » Fix: Created LenientTokenAuthentication that doesn't raise on token-not-found.
